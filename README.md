# Restaurant Booking API

REST API для бронирования столиков в ресторане.

API позволяет создавать, просматривать и отменять бронирования, проверяет доступность временных слотов и поддерживает фильтрацию и пагинацию списка бронирований.

## Репозиторий

GitHub: https://github.com/kit-kosatka/table-booking-api

## Стек

* Python 3.11+
* FastAPI
* Pydantic v2
* SQLAlchemy 2.0
* SQLite
* Alembic
* pytest
* httpx
* Docker

## Возможности

* создание бронирования;
* проверка доступности временного слота;
* получение списка бронирований;
* фильтрация бронирований по дате;
* пагинация списка бронирований;
* получение бронирования по ID;
* отмена бронирования без физического удаления;
* валидация входных данных;
* автоматическая API-документация Swagger и ReDoc;
* асинхронная работа с базой данных;
* тестирование API.

## Запуск проекта

### Клонирование репозитория

```bash
git clone https://github.com/kit-kosatka/table-booking-api.git
cd table-booking-api
```

### Локальный запуск

#### 1. Создание виртуального окружения

```bash
python -m venv .venv
```

Активация:

```bash
source .venv/bin/activate
```

Для Windows:

```bash
.venv\Scripts\activate
```

#### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

#### 3. Настройка окружения

Создать файл `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Создать директорию для базы данных:

```bash
mkdir data
```

#### 4. Применение миграций

```bash
alembic upgrade head
```

#### 5. Запуск приложения

```bash
uvicorn app.main:app --reload
```

После запуска API доступен по адресу:

```text
http://127.0.0.1:8000
```

## API endpoints

### Создание бронирования

`POST /bookings`

Создаёт новое бронирование.

Пример запроса:

```json
{
  "name": "Иван Иванов",
  "phone": "+79991234567",
  "booking_date": "2026-09-10",
  "booking_time": "18:00",
  "guests": 4
}
```

При успешном создании возвращается `201 Created`.

Если выбранный временной слот уже занят активным бронированием, возвращается `409 Conflict`.

### Получение списка бронирований

`GET /bookings`

Возвращает список бронирований.

Поддерживаются следующие параметры:

* `date` - фильтр по дате;
* `page` - номер страницы, по умолчанию `1`;
* `limit` - количество записей на странице, по умолчанию `10`, максимум `100`.

Примеры:

```text
GET /bookings
GET /bookings?date=2026-09-10
GET /bookings?page=2&limit=10
GET /bookings?date=2026-09-10&page=2&limit=10
```

### Получение бронирования

`GET /bookings/{id}`

Возвращает бронирование по его идентификатору.

Если бронирование не найдено, возвращается `404 Not Found`.

### Отмена бронирования

`DELETE /bookings/{id}`

Отменяет бронирование без физического удаления записи из базы данных.

Статус бронирования изменяется на `cancelled`.

Если бронирование не найдено, возвращается `404 Not Found`.

Отменённое бронирование не блокирует временной слот для нового бронирования.

## Валидация

При создании бронирования проверяются:

* имя - минимум 2 символа, только буквы, пробелы и дефис;
* телефон - формат `+7XXXXXXXXXX` или `8XXXXXXXXXX`;
* дата - от текущего дня до 90 дней вперёд;
* время - с 12:00 до 22:00 с шагом 1 час;
* количество гостей - от 1 до 12.

Ошибки валидации возвращаются с HTTP-статусом `422 Unprocessable Entity`.

## Тестирование

Для запуска тестов:

```bash
pytest
```

Тесты используют отдельную SQLite-базу в памяти и не изменяют основную базу приложения.

Текущий набор тестов проверяет:

* создание бронирования;
* конфликт занятого слота;
* получение списка;
* фильтрацию по дате;
* пагинацию;
* получение бронирования по ID;
* обработку отсутствующего бронирования;
* отмену бронирования;
* повторную отмену;
* возможность повторного бронирования отменённого слота;
* валидацию имени, телефона, даты, времени и количества гостей.

## Архитектура

Проект разделён на несколько слоёв:

```text
API
 ↓
Service
 ↓
Repository
 ↓
SQLAlchemy / Database
```

* **API** - обработка HTTP-запросов, параметры запросов и HTTP-ошибки.
* **Service** - бизнес-логика приложения.
* **Repository** - работа с базой данных через SQLAlchemy.
* **Schemas** - валидация входных и выходных данных через Pydantic.
* **Models** - ORM-модели SQLAlchemy.

## База данных и миграции

Для работы с базой данных используется SQLAlchemy 2.0 в асинхронном режиме.

Миграции базы данных выполняются с помощью Alembic:

```bash
alembic upgrade head
```

Откат последней миграции:

```bash
alembic downgrade -1
```

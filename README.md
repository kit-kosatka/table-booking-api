# Restaurant Booking API

REST API для бронирования столиков в ресторане.

API позволяет создавать, просматривать и отменять бронирования, а также проверяет доступность временного слота.

## Стек

* Python 3.11+
* FastAPI
* Pydantic v2
* SQLAlchemy 2.0
* SQLite
* Alembic
* pytest
* httpx

## Запуск проекта

### 1. Создание виртуального окружения

```bash
python -m venv .venv
```

Активация:

```bash
source .venv/bin/activate
```

Для Windows:

```bash
.venv\Scripts\activate
```

### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 3. Настройка окружения

Создать файл `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

### 4. Применение миграций

```bash
alembic upgrade head
```

### 5. Запуск приложения

```bash
uvicorn app.main:app --reload
```

После запуска API доступен по адресу:

```text
http://127.0.0.1:8000
```

## API endpoints

### Создание бронирования

`POST /bookings`

Создаёт новое бронирование.

Пример запроса:

```json
{
  "name": "Иван Иванов",
  "phone": "+79991234567",
  "booking_date": "2026-09-10",
  "booking_time": "18:00",
  "guests": 4
}
```

При успешном создании возвращается `201 Created`.

Если выбранный временной слот уже занят, возвращается `409 Conflict`.

### Получение списка бронирований

`GET /bookings`

Возвращает список всех бронирований.

Для фильтрации по дате используется параметр:

`GET /bookings?date=2026-09-10`

### Получение бронирования

`GET /bookings/{id}`

Возвращает бронирование по его идентификатору.

Если бронирование не найдено, возвращается `404 Not Found`.

### Отмена бронирования

`DELETE /bookings/{id}`

Отменяет бронирование без физического удаления записи из базы данных.

Статус бронирования изменяется на `cancelled`.

Если бронирование не найдено, возвращается `404 Not Found`.

Отменённое бронирование не блокирует временной слот для нового бронирования.

## Валидация

При создании бронирования проверяются:

* имя - минимум 2 символа, только буквы, пробелы и дефис;
* телефон - формат `+7XXXXXXXXXX` или `8XXXXXXXXXX`;
* дата - от текущего дня до 90 дней вперёд;
* время - с 12:00 до 22:00 с шагом в 1 час;
* количество гостей - от 1 до 12.

Ошибки валидации возвращаются с HTTP-статусом `422 Unprocessable Entity`.

## Тестирование

Для запуска тестов:

```bash
pytest
```

Тесты используют отдельную SQLite-базу в памяти и не изменяют основную базу приложения.
